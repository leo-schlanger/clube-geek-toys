## 2. O bug relatado — causa raiz

### Não era o que parecia

Verificado direto contra a produção antes de tocar em código:

| Camada              | Teste                                                                 | Resultado                      |
| ------------------- | --------------------------------------------------------------------- | ------------------------------ |
| Schema              | `products.videos`, `has_variants`, `variant_axes`, `product_variants` | ✅ existem                     |
| `POST /products`    | payload com `videos[]`                                                | ✅ 201, vídeo gravado          |
| `PUT /:id/variants` | 2 eixos + 2 SKUs                                                      | ✅ 200, `hasVariants=true`     |
| `POST /:id/video`   | MP4 real de 11 KB                                                     | ✅ 201, servido em `video/mp4` |
| Logs da API         | 120h de 4xx/5xx                                                       | ✅ nenhum erro nessas rotas    |

**A API sempre funcionou.** As requisições nunca eram enviadas.

### A causa

`ProductModal.handleSubmit` lia apenas o **estado confirmado**, ignorando o que
estava digitado no campo:

| O admin faz                            | Estado lido no save  | Resultado antes                   |
| -------------------------------------- | -------------------- | --------------------------------- |
| Preenche `Cor` → `Rosa, Preto` e Salva | `variantRows` = `[]` | `PUT /variants` **nunca chamado** |
| Cola link do YouTube e Salva           | `videos` = `[]`      | Vídeo descartado                  |
| Cola URL de foto e Salva               | `images` sem a URL   | Foto descartada                   |
| Cola URL de foto de variação e Salva   | `row.images` sem ela | Foto descartada                   |

Em todos os casos o painel exibia **"Produto criado!"**. Nenhum erro, nenhum
aviso — daí a sensação de que "o cadastro não funciona".

A matriz de SKUs só nascia ao clicar em **"Gerar combinações"**. Quem preenchia
os eixos e ia direto no Salvar não gerava SKU nenhum.

### A correção

`handleSubmit` agora resolve todo rascunho pendente **antes do primeiro write**:

- `resolvePendingVideos()` / `resolvePendingImages()` / `resolvePendingVariantImages()`
- `mergeVariantMatrix()` monta os SKUs que faltam a partir dos eixos
- Rascunho **inválido bloqueia** o save com mensagem, em vez de sumir calado
- "Ativar" marcado sem tipo/opção agora avisa em vez de salvar mudo

Regra de destruição, deliberada:

| Caminho                     | Comportamento                                                                                            |
| --------------------------- | -------------------------------------------------------------------------------------------------------- |
| Botão **Gerar combinações** | Refaz a matriz: combinação removida dos eixos **some**                                                   |
| **Salvar** (merge)          | Só **acrescenta**. Nunca apaga linha — ela pode ter estoque e foto. Avisa se sobrar linha fora dos eixos |

Cobertura: 6 casos novos em `ProductModal.test.tsx` (bloco _"rascunho pendente no Salvar"_).

### 🔴 Achado crítico: certbot parado

```
clube-geek-certbot   Exited (143) 3 weeks ago
```

O container que roda `certbot renew` a cada 12h **estava parado desde ~25/07**.
O certificado (SAN de 14 domínios) vence em **17/10/2026** e a janela de
renovação abre por volta de 17/09. Sem intervenção, em 17/10 caem `club`,
`shop`, `adm`, `api`, `analytics` e `radio` — nos dois domínios espelho.

Por que passou batido: o deploy roda
`docker compose up -d --force-recreate api nginx` — **só api e nginx**. O certbot
recebeu SIGTERM em algum restart e, com `restart: unless-stopped`, nunca voltou.

**Resolvido agora:**

1. Container religado na VPS — já lê a config e responde
   `Certificate not yet due for renewal ... expires on 2026-10-17`.
2. Webroot ACME validado de ponta a ponta: gravei um arquivo de prova em
   `/.well-known/acme-challenge/` e busquei por HTTP em `club`, `api`, `shop`,
   `adm.geekpoptoys` e `radio` — os 5 responderam. A renovação de setembro vai passar.
3. `deploy.yml` agora sobe o certbot em todo deploy (`up -d certbot`, sem
   `--force-recreate`).
4. **Segundo furo, latente:** o nginx lê o certificado uma vez no boot. Mesmo com
   o certbot funcionando, ele continuaria servindo o cert antigo até alguém
   reiniciá-lo. Funcionava por acidente, porque todo deploy recria o nginx.
   Adicionado loop de `nginx -s reload` a cada 6h no `docker-compose.yml`.

### ⚠️ Build cache de 24.5 GB

`docker system df` mostra **24.3 GB recuperáveis** em build cache, efeito do

## 12. Segunda leva — os cinco resolvidos no mesmo dia

### E2E de variação e vídeo

clicar em "Gerar combinações" nem em "Adicionar": ele preenche os eixos, cola o

### CSP nas SPAs

Em `server/nginx/shared-headers.conf`, que já é incluído pelos três blocos
(club, shop, adm). O que mais importa aqui é `connect-src`: mesmo que alguém
injete script, o JWT do `localStorage` não sai para um host de fora.

Sem `'unsafe-inline'` e sem `'unsafe-eval'` em `script-src`. Duas decisões que
saíram de medição no navegador, não de suposição:

| Pergunta                                                | Resposta medida                                                                                                                                                                             |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Hash dos scripts inline ou externalizar?                | **Externalizar.** O `index.html` mudou 16 vezes (uma delas hoje); hash desatualizado quebraria a página em silêncio. Foram para [`public/boot.js`](../public/boot.js).                      |
| `<script type="application/ld+json">` viola script-src? | **Não.** Com 3 blocos ld+json na página, o navegador reportou só as 2 violações dos scripts executáveis.                                                                                    |
| Precisa de `'unsafe-eval'`?                             | **Não.** O `eval` vinha de uma sondagem do zod (`try { new Function("") } catch`), que cai sozinha no caminho alternativo. Validei o cadastro com o CSP ligado: a validação dispara normal. |

`/boot.js` ganhou um `location =` próprio no nginx: sem hash no nome, ele não
podia cair na regra `immutable` de 1 ano dos `.js`.

A sonda ficou versionada em [`scripts/qa/csp-probe.mjs`](../scripts/qa/csp-probe.mjs)
— ela injeta uma policy candidata nas respostas da produção e navega por 8 telas
coletando violações. **Rode antes de subir qualquer integração externa nova**,
senão o host que faltar na policy morre calado no navegador do cliente.

para limpeza nunca derrubar deploy. Rodado na hora: **34 GB → 24 GB** (36% → 25%
